`index.html` בשורש הוא עמוד משותף שמקשר לשתי הגרסאות. כל מודל משנה בו רק את החלק של הגרסה שלו.

## כללי עבודה משותפת

- לפני כל שינוי: `git pull`. אחרי השינוי: commit ו־push מיד.
- כל מודל עובד בתיקייה שלו. לא משנים קבצים בתיקייה של השני.
- רוצים להציע שינוי לגרסה של השני? כותבים אותו ל־`NOTES.md` בשורש, ורז מעביר.

## גרסת קלוד

התוכן נמצא ב־`claude/src/`. הדפים נבנים עם `python3 claude/build.py`, ואת `lesson-*.html` ו־`index.html` שבתיקייה לא עורכים ידנית.

## מכונת אווירות

אפליקציה עצמאית, בתיקייה `synth/`, בכתובת משלה ובלי קישורים לשיעורים. אין שלב בנייה: עורכים ישירות את `engine.js` (הצליל), `app.js` (הממשק) ו־`style.css`.
כשמשנים קבצים, מעלים את מספר הגרסה ב־`CACHE` שב־`sw.js`, כדי שמכשירים שהתקינו את האפליקציה יקבלו את העדכון.

## המטבח

אפליקציה עצמאית בתיקייה `kitchen/`, בלי קישור מהעמוד הראשי ועם `noindex`. זו הגרסה היחידה שמתחזקים. בדף הציבורי אין שמות של אנשים.

**איך מעדכנים:**
- **מזונות ודירוגים:** הכל בבלוק `RAW` בראש הסקריפט ב־`index.html`. שורה לכל מזון: `קטגוריה;דירוג;שם/שם נרדף/...;הערה;חלופה/חלופה`. השם הראשון הוא מה שמוצג, השאר רק לחיפוש.
  - קטגוריות: `veg` ירקות, `protein` חלבון, `carb` פחמימות, `fat` שומנים, `fruit` פירות, `spice` חליטות ותבלינים, `cook` שיטות בישול, `rule` מהכללים.
  - דירוגים: `5` `4` `3` `2` כמו במסמך, `x` להפחית עד להפסיק, `q` לברר עם אור, `i` טוב לדעת.
  - חלופות: רק אם רוצים חלופות מסוימות. בדירוג 2 בלי חלופות, מוצגים אוטומטית המומלצים ביותר מאותה קטגוריה.
- **שורת החליטות למעלה:** המערך `TEAS`.
- **תבניות הצלחת:** המערך `PLATES`.
- **הכללים והשאלות לאור:** HTML רגיל בלשונית `p-rules` (השאלות ב־`#askList`).
- **אחרי כל שינוי:** מעלים את מספר הגרסה בשני מקומות: `CACHE` ב־`sw.js` (`kitchen-app-N`) והתווית "גרסה N" בכותרת של `index.html`. ככה האפליקציה במסך הבית מציגה "יש גרסה חדשה", ורז רואה איזו גרסה פתוחה אצלו. הניקוי במטמון מסונן לפי הקידומת `kitchen-`.
